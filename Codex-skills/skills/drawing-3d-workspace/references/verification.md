# Verify behavior, then qualify the claim

Model records do not prove visible output. Build an independent source requirement inventory and a per-consumer eligibility matrix: required when enabled, intentionally hidden when disabled, ineligible in this view, or unsupported. For a bounded correction, identify required features/dimensions, affected consumers and protected records before editing. Trace source evidence → local coordinates → solved shape → project/view eligibility → renderer → visible output. Check mirrored face/camera bases, actual manifest/include rules, hidden owners and configuration before changing position or depth to guess at occlusion. Check actual 3D pixels/visibility and exported SVG/HTML geometry, not just arrays or matching counts generated by the same code. Inspect a small staged affected-view preview and its distinctive internal contours before full-set generation.

Select tests proportional to the requested change: start with affected source, geometry, visibility and exports. Expand coverage when shared code or dependencies change or the user explicitly requires it; the following are relevant cases, not a mandatory full-suite rerun for every correction:

- Source dash fragments: exact endpoints, direction, owner, segment coverage and no second dash pattern. Inject missing/reversed/incorrect-owner fragments in actual exports.
- Visibility: enabled versus disabled pixels on the unobstructed front, identical pixels behind opaque foreground geometry or on the back, orbit-updated facing, hide/isolate and source-matched camera rules.
- Controls: default off, repeated toggles, independent annotations/tabs, disabled unsupported-symbol state, checking SVG and offline/fallback consistency. Check that toggles preserve geometry, dimensions and history.
- Spatial edits: dependency propagation, inferred/dependent yellow dimensions, rejected constraint violations, revision conflicts, undo/redo, save/reopen and import/export.
- Relationship dimensions: verify source inventory to selection coverage, including each registered child/group, actual numeric/witness graphics, confirmed centers versus provisional envelopes, explicit camera alignment, hidden selection and edit propagation. Use a synthetic non-customer project to reject identifier-specific implementations. Mutate missing relationships, wrong subjects, reversed/shifted witnesses, wrong values/backgrounds and data-present/graphics-absent exports; record omissions explicitly rather than substituting size labels.
- Isolation/startup: two synthetic projects in separate tabs, no cross-project preview/commit/import/evidence/export; ordinary-shell launch without build tools, repeat launch, missing runtime and foreign-port preservation.
- Portable delivery: inspect the exported file offline, network requests, lack of edit actions, desktop scaling, phone viewport and WebGL-disabled fallback. Record emulation separately from hardware tests.

Use the requested new revision directory, isolated databases and artifacts. Before replaying an old generator, publisher or test script, inspect writes and import side effects; do not overwrite historical evidence just to obtain a fresh pass. Keep exploratory builds out of customer history. After corrections and required final repeatability checks, publish the reviewed candidate once and verify its hashes. For unchanged implementations, cite dated behavior results as historical evidence. Instruction-only updates use fresh decision cases and skill validation without customer application rebuilds; these validate procedure choices, not new visual performance or unseen-customer reconstruction.

Use existing runtime resolvers and targeted searches; stage managed skill files without copying historical versions. After two unsuccessful diagnostic attempts without new evidence, reduce to a minimal reproduction. When an unrelated environment failure is demonstrated, stop repeating the full pipeline, report the limitation and continue safe independent checks. Distinguish observed failure from uncertain cause; do not waive blocked required tests or declare a runtime broken without evidence.

Tie source review, geometry consistency, export correctness, layout, visual inspection, repeatability and customer acceptance to separate records with exact artifact hashes. A changed artifact invalidates its applicable review. Two identical builds establish repeatability, not source accuracy. Preserve original uncertainties and report unperformed checks as pending/not performed.

For skill updates, inspect the instruction diff for scope creep, weakened checks and project constants. Stage, validate frontmatter/links/lesson records, take fresh workspace and installed fingerprints, then use guarded updates with recoverable snapshots. Never overwrite previous learning records; append a scoped supersession. Freeze a new package only when explicitly requested, preserving earlier anchors and testing its restore procedure in an isolated target. A workflow snapshot does not grant customer drawing approval, fabrication certification or proof on another customer's PDF.
