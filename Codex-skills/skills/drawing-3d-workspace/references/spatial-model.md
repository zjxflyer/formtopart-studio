# Spatial model and edit boundaries

## Reusable relationship-dimension rule

Classify retained source dimensions as component sizes or object-to-object/datum relationships; explicitly record omissions. Register relationships as project data with stable selectable subjects, structural anchor pairs, measurement direction/basis, source views, evidence and measurement-specific uncertainty. Resolve them through the shared solver and preserve them through preview, JSON round trips, revisions and restoration. Never encode one customer's IDs or values in generic selection/rendering logic. Legacy size-only compatibility is not a source-relationship coverage pass.

When the user selects a dimensioned component, default to its source-supported relationships and make its own sizes separately available. Explicit group subjects can expose the same relationship set through multiple children without duplicate IDs. Preserve the camera on selection and offer an explicit alignment action for the matching source view; do not resize or move physical geometry to improve dimension appearance. Respect hidden selections, isolate and view eligibility. Keep display changes out of revision history.

Use one projected annotation path across live 3D, checking SVG, offline HTML and fallback. Draw complete dimension graphics, preserve structural endpoints while routing clear readable lanes, and recalculate layout during orbit/resize. Disclose edge-on readings and provide alignment rather than a false projected length. Derive yellow styling from uncertainty necessary to the measurement; a provisional fixture envelope must not contaminate independently confirmed center datums. Preserve source observations when edits alter current measurements.

Match plan footprints/depths to elevation heights, divisions, visible faces and source witnesses. Record local axes, source datum and view transforms explicitly; page-up is not geographic north. Preserve recursive ownership, curves, narrow members, rails, continuous bands, stepped bases, slat gaps and actual openings. Material-region bounds are not automatically physical strokes or solids.

Keep source-evidence views and generic orthographic quick cameras in separate namespaces and controls. Source views retain project-owned mappings and filtering; quick cameras use local axes and the complete model, subject to existing hidden/isolate controls and actual physical occlusion. Never invent geographic north or use customer sheet IDs as generic face names. A bottom preset looks upward from negative Z with a right-handed, non-mirrored camera basis. Share the resolver across live, offline and disclosed WebGL fallback; retain annotation eligibility separately and create no model revisions.

Quick snapping preserves zoom/frustum scale, orbit target, selection and display state. For the owner's selected Z-up turntable convention, keep horizontal yaw on MODEL Z and vertical pitch on inclination; a preset changes pose, not input-world axes. Preserve explicit heading at exact poles: horizontal drag spins the top/bottom in its plane, while inward pitch leaves the pole without a roll jump. A hidden safe-pole input is permitted only when the rendered preset remains exactly square. Preserve default drag signs, sensitivity, damping, pan and zoom. Clear the current-preset indicator after manual orbit leaves it; clicking that preset again must re-snap.

Matching camera-relative motion does not prove consistent model-relative orbit. First demonstrate a physical-axis regression against the previous implementation, then compare actual signed, diagonal and repeated drags with an independent unmodified default controller. Assert world-Z yaw, unchanged inclination during yaw, no unintended roll, pole departure and production damping for every preset; do not cancel the same pose transform in the test oracle. Fit is explicit and fits the current orientation. Validate delivered CSS/runtime and distinctive affected views before publication, since presentation failures can masquerade as omitted components. This supersedes earlier camera-local-equivalence claims; preserve those lesson records as dated history.

Solve confirmed geometry first. Resolve necessary unknowns in order: exact dimension-chain arithmetic, matched cross-view endpoints, calibrated source measurement. Record original observations, alternatives, method/formula, uncertainty, evidence and affected objects. Highlight provisional values and dependent dimensions on pale yellow. Do not silently resize confirmed neighbours to close conflicts or imply unsupported precision. When no defensible value exists, leave only the affected geometry pending and explain its effect on the view.

For click-to-edit interaction, select the same stable owner in the model and recursive tree. Support only properties the model can solve. Preview changed and dependent objects before applying; report constraint failures without stretching neighbours. Derived measurements expose their controlling inputs rather than accept inconsistent direct edits. Mark manual amendments as amendments, not source confirmation.

Use revision-checked commits, local revision history, undo/redo and restoration that retain previous states. Bind preview tokens, import/export and browser state to the selected project. Generate linked plan/elevation checking drafts from the current solved model, clearly separate from historical delivered drawings. Export new revisions rather than replacing approved or frozen outputs.

For partial requests, preserve unaffected geometry, dimension bindings, history and exports. A caption or visibility change should not trigger a new reconstruction or model revision. Only propagate a shared geometry change when the evidence or applied user edit actually changes that shared object.
