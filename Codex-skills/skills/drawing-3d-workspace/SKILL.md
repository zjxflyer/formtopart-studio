# Evidence-based drawing 3D workspaces

Use one spatial model with recursive children and stable IDs, not drawings pasted onto planes. Reuse the existing application and project schema where feasible. Use `$elevation-create-and-audit` for source reconstruction, simplified 2D presentation and source/dimension audits; use this companion for spatial coordination, interaction and delivery. Do not invoke 3D work merely because a user requests 2D drawings or a lesson summary.

## Choose the relevant procedure

- For reconstruction, inference, synchronized checking views or edits, read [spatial-model.md](references/spatial-model.md), including the shared component-size versus relationship-dimension rule.
- For annotation controls, operation marks, viewport behavior or portable HTML, read [viewing-and-export.md](references/viewing-and-export.md).
- For customer-project separation, launch failures or history migration in a drawing workbench, read [projects-and-startup.md](references/projects-and-startup.md).
- For a local correction or missing visible feature, and before releasing, promoting lessons or freezing a workflow, read [verification.md](references/verification.md). Trace the affected consumer before speculative geometry edits; keep exploration and tests bounded to the requested change.

Separate source observations, semantic assemblies, solved physical geometry, materials and annotations. Dimensions, descriptions, view references and operation marks never become solid edges or selectable construction. A symbol cannot establish a hinge, divider or drawer mechanism without independent evidence.

## Owner preferences, not universal standards

Unless overridden by the current request, use white faces and black outlines, optional restrained material colors, blue dimensions and pale-yellow numeric backgrounds for provisional or dependent inferred values. Keep uncertainty and provenance in data. Do not turn conflicted observations into confirmed source measurements.

Provide independent dimension, text, view-reference and operation-symbol controls. For supported door/drawer symbols use **Swing lines / 柜门／抽屉开启线**, initially off, with this visible/accessibility description:

> Door swing and drawer pull-out symbols. Display only—not an animation. / 柜门开启方向及抽屉拉出符号，仅显示符号，不是开启动画。

This is the owner's interface shorthand: drawers normally pull out, and a mark's exact meaning follows the project evidence. Preserve an existing internal option such as `openingMarks` during a wording-only change. This preference does not remove source-supported symbols from delivered static 2D drawings.

Keep dimensions, camera transforms, view identifiers, counts, paths and object-specific corrections in the customer project. Store reusable verified lessons separately from project facts, following the drawing skill's guarded learning procedure. No paid model call, source redesign, unrelated cleanup or historical overwrite is implied by operating this workspace.

Separate source-evidence views from generic orthographic quick views. A quick direction is a pose-only shortcut for the same complete 3D model: preserve default mouse-orbit behavior, zoom/frame scale, pivot, selection and display controls. Use local front/right/back/left, page-relative top rotations and true underside rotations, never geographic north or customer sheet IDs as generic face names. These presets are not new geometry or evidence; annotations still require valid view eligibility. See [spatial-model.md](references/spatial-model.md) for the interaction boundary.

For this owner's Z-up turntable convention, horizontal dragging always rotates around the model's vertical Z axis, including at exact top/bottom views. Matching camera-relative motion does not prove consistent model-relative orbit: verify the physical rotation axis, constant inclination under yaw and pole behavior against an independent default-controller baseline. Do not rotate the input coordinate frame with a camera shortcut.

Keep complete-model geometry visibility, source annotation eligibility and framing independent. For this owner's confirmed interaction, source-linked cameras center and fit the visible model including room context; pose-only quick directions preserve pivot and scale. Fit explicitly recenters and fits. Source-filtered checking drawings remain separate representations, not geometry exclusion rules for 3D. See [viewing-and-export.md](references/viewing-and-export.md) for consistent size controls and empty-state feedback. Before publication, inspect the actual delivered portable stylesheet and one distinctive affected view, because a runtime styling failure can look like missing geometry.
