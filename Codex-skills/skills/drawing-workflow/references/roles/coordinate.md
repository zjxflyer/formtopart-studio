# Coordinate

Own overall scope and the single shared-state writer identity. Read current user amendments, project manifest/state, actual worker status and exact claims before dispatch or continuation. A claim is ownership, not proof of activity; worker completion is not drawing acceptance.

Maintain the persistent to-do register described in [todo-list.md](../todo-list.md). Before dispatching new user feedback, save a stable task ID, unchanged original request/source, affected sheets/stage, priority, dependencies, owner and current status. Clarify genuine ambiguity while continuing independent work; do not replace the whole queue with the newest message. Record supersession/cancellation with reason rather than deleting history. DONE requires concrete completion evidence; drawing tasks additionally require the applicable independent check and summary. A worker finishing, a file existing or a check merely starting is not DONE.

Reassess each task before starting, resuming or reassigning it. Compare its original purpose with the latest relevant user instructions, current source/artifact/check state, completed work and prerequisites. Decide whether to proceed, refine the execution plan, split or replace the task, defer/block it, cancel it as explicitly no longer required, or close it with existing completion evidence. Preserve the original request; link replacements and explain why the old task is superseded. Obsolete work is CANCELLED or SUPERSEDED, not falsely DONE. A new interpretation must not silently expand scope or erase an unresolved obligation. Ask only if a consequential conflict cannot be resolved from current authorization, while continuing unrelated work.

Before marking IN_PROGRESS, record a fresh context review using the current state hash, reason and relevant source references as specified in the helper contract. This mechanical freshness check proves which state was considered; the coordinator must still reason about semantic relevance. Recheck immediately before dependent work or publication if later instructions, outputs or findings could change the decision. New intake does not automatically cancel unrelated work already running. Keep an auditable explanation when priorities, ownership, dependencies or scope change.

At each meaningful update and continuation, show what is active, next, blocked/deferred and newly completed, with current result links. Generate the task-list/index view from the saved register and checkpoint it with workflow state. New tasks do not reset sheet round budgets; record an explicit user-authorized scope amendment separately when necessary.

1. Derive ordered sheets and actual totals from the current manifest. Name tasks by role + exact sheet + stage. Do not reuse another sheet's name. Give each worker an exclusive revision area and exact source/candidate pins; roles stay independent.
2. Apply the phase gates and separate counting conventions. Announce sheet, stage, major round N/2, correction number and bounded scope in the main chat before each repair. Summaries and infrastructure retries cannot silently reset or increase the allowance.
3. Keep dependencies sequential; allow only independent reached-sheet work to overlap within actual capacity. One coordinator writes shared index, queues, publication and checkpoints. Check runtime health separately; do not kill workers or erase claims merely because a timer expired.
4. After each check, relay meaningful corrections, actual source/before/after comparisons as applicable, verdict and absolute current result links. Record Summary/SKIP before the next dependent action. Publish candidate versus independently reviewed status accurately.
5. Refresh that sheet's index immediately when an output/status changes, save state and checkpoint. Organize its backend when reached. Split legacy grouped deliveries into own-sheet entries without moving frozen history or inventing absent views.
6. Before final assembly, verify every selected own Plan/elevation packet and exact hashes, eligible scope, ordering and limitations. Check the combined PDF and its actual contents/destinations. Do not label partial/provisional output unqualified complete.

When interrupted, reconcile checkpoint, input and output hashes, summaries, counters and real worker state; resume the next authorized step. Preserve an explicit handoff before reopening. No permanent application-health fix, autonomous watchdog or session-database modification is part of this workflow.

Use the requested model/effort if supported; otherwise state the limitation instead of silently downgrading. Fast service speed changes neither normal verification nor the acceptance standard. Maintain current authorization; no routine confirmation waits are needed for already authorized reversible work, but genuine missing evidence remains explicit.
