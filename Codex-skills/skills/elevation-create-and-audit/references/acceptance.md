# Independent acceptance

## Evidence tied to this run

Each new generation starts with visual review pending. Store reviewed artifact hashes, source references, reviewer identity, findings, unresolved issues, and review scope separately from generator constants. A changed artifact invalidates the applicable review. Regression status comes from the executed test and result; reproducibility status comes from comparison of independently generated files. Never derive one from the other or hardcode success into a renderer.

Maintain a dedicated source-review record. It must identify the evidence actually inspected, the findings, unresolved issues, and hashes of the reviewed outputs. A visual-status option or flag may update only the visual-review record; it must never set, imply, or promote source-review status. Deliberately stale one reviewed hash and require the ordinary source-review validator to reject it.

Build the source-requirement inventory independently of generated component, symbol, dimension, and label lists. Validate output coverage against that inventory by stable identity and evidence. Searching a generated label in the same generated list, comparing a mutated list with its original, or checking only that two lists differ cannot discover a source omission.

For multi-consumer symbols, distinguish required coverage when enabled, intentional default-off hiding, view-ineligible records and unsupported projects. A model's symbol array does not establish visible 3D, draft, SVG or offline-HTML coverage. Inspect the actual consumer and mutate missing fragments, reversed endpoints, wrong owners and double-dashed native fragments. Treat toggles as annotation state, requiring unchanged geometry, dimension bindings and model history; use the 3D companion for facing/occlusion and portable-viewer checks.

Also inventory excluded content and reject its reappearance in actual exports. Check removed callouts as complete annotation chains, retained recognizable silhouettes, crop-crossing true boundaries, repaired fixture-mask intervals, and clearance for newly inferred dimensions using [simplification.md](simplification.md). Exclusion of a lamp must not remove an evidenced board edge or fill a genuine opening. Skill-version acceptance does not grant customer approval of its example drawings.

When clean-output policy excludes generic source/reference marks, scan actual SVG/PDF/PNG for their reappearance, including repeated short segments and solid-converted paths. Source-verified `opening_operation` marks are a separate permitted annotation layer, not generic references or numeric dimensions. Validate their native endpoints, pattern and owner against an independently reviewed source register. Test missing/reversed/wrong-owner marks and accidental conversion into physical edges. Do not classify every diagonal as an opening mark: handle hardware remains physical. Keep source IDs, locations and reasons in audit registers; required plan view-reference arrows are a separate allowed layer.

For coordinated plan/elevation sets, independently verify every registered view reference against source identifiers and directions. Test missing/duplicate markers, incorrect sheet/detail/target, reversed triangles, unreadable text, collisions, and unregistered circles. Do not weaken exclusion tests by permitting every circle or triangle. For an annotation-only change, require unchanged physical geometry, dimensions/bindings and unaffected exports; replace only the corresponding combined-set page or preview panel.

Maintain separate source-fidelity, geometry, dimension-consistency, layout, visual, reproducibility, and approval results. Identical incorrect outputs can pass reproducibility while failing source fidelity. A successfully detected unresolved dimension conflict blocks approval. Review a diff against explicit allowed changes; unchanged area is required for a representation-only correction, but newly evidenced physical components require a documented area delta.

For local edge edits, independently test visible interval coverage from every owner. Mutate each duplicate contributor separately, the orientation of the target, a protected adjacent edge, and the review hash. For symbol edits, test a reversed but fully contained mark and a wrong owner. Checks derived solely from the same assumptions as the renderer cannot establish source fidelity.

Before invoking historical generators, inspect import-time writes. Use immutable inputs and isolated copies when imports mutate extraction data; verify historical hashes afterward. Start with the affected source, geometry, visibility and export checks; broaden regression coverage only when changed shared code or dependencies justify it, or the user requires it. Identify unchanged dated results as historical, not fresh passes.

After two unsuccessful diagnostic attempts without new evidence, reduce the failure to a minimal reproduction instead of repeating the full pipeline or changing geometry speculatively. If that demonstrates an unrelated environment failure, report its proven scope, leave uncertain causes unresolved, and continue safe independent checks. Do not silently waive a blocked required test or publish as fully validated.


1. Source audit: trace each source component, relevant dimension, material region, and retained symbol to a model record or explicit justified exclusion. Check for unsupported extra structure as well as omissions. Derive counts from the inventory.
2. Geometry audit: recompute polygon edges, adjacency, overlaps, gaps, connected assemblies, openings, narrow members, continuous bands, and toe-kick interruptions. Confirm representation symbols do not alter component inventory, material areas, geometry, or equations.
3. Dimension audit: independently calculate endpoint differences and chain totals; verify bindings against source witness lines. Check record-to-render and schedule-to-render coverage, duplicates, and inference provenance.
4. Layout audit: check labels against labels, outlines, unrelated annotation lines, material notes, schedules, and page bounds. Resolve conflicts deterministically or fail; do not unconditionally set readability to pass.
5. Artifact audit: inspect actual glyph regions against a text-free render or equivalent glyph-sensitive comparison, so nearby lines cannot satisfy visibility. Check inferred/confirmed background colors, rotations, clipping, and cross-format alignment. Inspect PDF vector content, embedded fonts, crop, and rasterized detail.
6. Symbol audit: compare the project symbol profile to each rendered mark. Verify orientation, line pattern, owner face, and clipping; keep physical seams independent. Test a clear-appearance/unknown-meaning case and identical marks with different project meanings.
7. Visual review: compare source, final drawing, and relevant material/assembly, dimension-binding, edge, symbol, and label-layout views. Inspect whole-page and detail scales. Record who/what reviewed which artifacts and findings; absence of a review is pending, not passed.
8. Release: preserve the last accepted pass and keep exploratory builds unpublished. After corrections, generate twice in separate staging locations and compare deliverable hashes. Normalize nonsemantic timestamps where needed. Publish the reviewed candidate once, verifying promoted hashes against the reviewed artifacts; a later evidenced correction starts another bounded change rather than overwriting history. Instruction-only skill updates use decision cases and skill validation, not customer application builds or drawing regeneration.

For every component whose model implies a closed or enumerated contour, inspect the exported SVG or equivalent vector output for the ordered exported coordinates, each expected edge, exact endpoints, corner connectivity, stroke pattern, and color. Deliberately test missing, shortened, flattened, shifted-junction, dashed, recolored, and annotation-substituted edges. At least one relevant fault set must alter only the export while leaving the correct canonical model unchanged. A complete component record does not prove that the renderer emitted its edges.

For every required solid physical outline, also audit interval continuity independently of the renderer: compare the complete source-reviewed contour register with the actual exported intervals, reject accidental internal breaks and opaque label-mask occlusion, and require every blank interval to be registered as a genuine opening, space, or separate component boundary. This rule does not convert source-supported opening/reference symbols to solid lines.

For non-rendering assembly containers, inspect actual exports to confirm that their bounds produce neither a connecting stroke nor an opaque fill. Sample each intentional gap while separately checking that every required child edge remains complete. Deliberately restore a container perimeter, cover a gap with fill, and remove a child edge; the ordinary validator must reject all three defects.

Before a local correction, freeze the prior reviewed artifacts and define the permitted changed regions or records. Compare the new SVG/PNG/PDF against that baseline and fail when unexplained changes occur outside the allowance. Record review findings against the hashes of the actual compared artifacts.

Use regression mutations appropriate to changes: remove a visible dimension or one of its graphic parts, change an endpoint, add a standalone measurement value, append `INF`, add an unsupported divider, omit a narrow member, cross an owner polygon with a mark, infer geometry from an X or V, remove a physical seam, overlap labels, shorten a continuous LED band, or recolor an object edge as a dimension. Establish a clean baseline first. Send each mutation through the normal validator and, for rendering defects, inspect an actually regenerated or mutated export rather than only an in-memory record. Each relevant case must be detected by the corresponding audit. Passing arithmetic or collision checks alone never proves source fidelity.

For stepped bases and cross-view residuals, additionally mutate the short interval's endpoint, flatten the polygon step, change the shared inferred height in one view, remove a wall-base junction, and stretch an adjacent confirmed span. The normal validator must reject each exported defect while the unchanged downstream dimensions remain stable.

Report a candidate's verified source coverage separately from unresolved source conflicts. A visually accepted correction may supersede an earlier review while still retaining an explicit pending dimension-chain or interpretation issue; do not convert that uncertainty into a shared rule.

Deliver the drawing PDF and requested SVG/PNG, extraction/model data, relevant audit views, defect report, test results, and manifest. Keep automated and visual status distinct. Do not claim new source comparison or tests based solely on historical reports.
