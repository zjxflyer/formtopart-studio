## Consolidated reusable lesson set

| Area | Reusable rule | Route or proof |
|---|---|---|
| Source reading | Reconcile visual inspection, OCR, native text, and native vectors. Preserve visible construction supported by contour or witness evidence even when a dimension has no readable number. | Source inventory plus explicit retain/exclude/unresolved decision |
| Component boundaries | Preserve thin members, countertops, dividers, returns, rails, stepped bases, and every closing edge. Simplify appliance interiors without removing coordination boundaries. | Recursive components, solved polygons, and exported-edge coverage |
| Operation symbols | Preserve each door or drawer mark's owner, orientation, convergence, segments, and dash pattern. A symbol never creates a seam by itself. | Project symbol profile and owner-bound symbol audit |
| Dimensions | Bind every visible value to two structural endpoints and complete dimension graphics. Use compact blue annotations outside the complete visible envelope with scalable clearance. | Independent source dimension inventory and record-to-render coverage |
| Inference | Use exact arithmetic and matched cross-view endpoints. Show only necessary resolved inferred values on pale yellow without `INF`; keep redundant, contradictory, or unresolved calculations internal. | Provenance record, endpoint equations, and cross-view correspondence |
| Base details | Model stepped cabinet toe kicks explicitly and distinguish them from wall bases. Apply residual widths only to the evidenced short interval. | Cross-view contour comparison and step-preserving mutations |
| Adding objects | Calculate occupied space and displacement, then translate complete affected assemblies with their children, symbols, annotations, and endpoints without resizing. | `$drawing-add-objects` |
| Extracting objects | Define inclusion boundaries, extract recursive records, preserve source identity and ownership, and rebind only relevant dimensions in local coordinates. | `$drawing-separate-objects` |
| Verification | Check source coverage and actual exports independently. Source review, geometry consistency, visual review, and repeatability establish different claims and need separate hash-bound records. | Independent audits plus export-only and stale-review mutations |

The first six rows are shared drawing rules. The two transformation rows intentionally remain procedural in their companion skills. The final row governs all three skills.

## Lessons from iterative customer correction

- Inventory and symbol records need independent source checks: a valid polygon can contain the wrong number of faces or a reversed symbol.
- Match marked orientation and endpoints before editing; trace every coincident contributor to a visible line.
- Keep closed material regions separate from visible physical edges. Preserve supported appliance outlines while rejecting invented geometry.
- Dimensioned thin construction and appliance coordination edges survive simplification. Height and horizontal placement require separate evidence.
- A repeated hash proves repeatability, not customer accuracy. Fresh review attaches to exact artifacts and has a defined scope.
- Later customer corrections can supersede previously passed reports. Keep the history and retire its interpretation explicitly.

These are workflow rules. Drawer segment counts, door orientation, dimensions, component IDs, and appliance coordinates remain project facts. No historical drawing is newly certified by this consolidation.
